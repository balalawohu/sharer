## 三、项目经历

### 趣分 · 资源共享平台（sharer）

> **项目描述**：支持图片、音频、视频资源上传与分享的全栈 Web 应用。用户可一键上传资源并控制公开/私有可见性，在广场浏览搜索他人资源，后台完成资源管理。前后端分离架构，采用 monorepo 双目录管理。
>
> **技术栈**：Vue 3 + Vite + Pinia + Axios ｜ Node.js + Express 5 + Sequelize 6 + MySQL 8 + JWT
>
> **项目地址**：https://github.com/balalawohu/sharer

#### 核心职责与产出

**1. 服务端分层架构设计（Controller / Service / Model 三层）**

- 搭建 `routes → controllers → services → models` 调用链路，明确各层职责边界：控制器只做参数提取与响应，业务规则统一沉淀到服务层（`ServiceError` 携带 HTTP 状态码，由控制器统一捕获兜底）
- 抽出 `utils` 通用层：统一响应格式中间件（`res.ok` / `res.fail`）、参数校验工具（手机号正则、邮箱格式、密码强度计分）
- 实现全局错误处理中间件，并针对 multer 的文件上传异常（超大小、超数量、类型非法）单独做错误转译，统一返回业务状态码

**2. 用户认证体系与安全设计**

- 基于 `jsonwebtoken` 实现登录鉴权，token 有效期 7 天；编写鉴权中间件，校验通过后挂载脱敏用户对象到 `req.user`，业务层无需重复解析
- 密码使用 bcrypt 加盐哈希存储（成本因子 10），返回数据前统一脱敏剔除密码字段
- 安全细节：账号不存在与密码错误统一返回「账号或密码错误」，避免攻击者探测已注册账号；登录支持手机号 / 邮箱双通道（`identifier` 字段二义匹配）
- 前端审查：密码强度计分算法（字符类别数 + 长度双维度，分弱/中/强三档）前后端共用同一套规则，杜绝「前端提示通过、后端拒绝」的不一致

**3. 存储抽象层：本地磁盘与云对象存储无缝切换**

- 设计 `local / qiniu` 双存储驱动，通过环境变量 `STORAGE_DRIVER` 一键切换，业务层代码零改动
- 本地模式：multer diskStorage 按资源类型分目录存储，文件名重写为 `时间戳-随机串.扩展名`，杜绝同名覆盖与路径穿越风险
- 七牛云模式：服务端流式上传（putStream）+ 上传成功后自动清理本地临时文件
- 实现**前端直传**方案：后端签发上传凭证，前端不经服务器直接传文件到对象存储，显著缓解服务器带宽压力；配套提供直传后的资源登记接口
- 文件类型白名单（仅放行 `image/*`、`audio/*`、`video/*`）、单文件 20MB / 单次 9 个的限制
- **容错设计**：落库失败时自动回滚已写入云端/磁盘的文件，避免产生孤儿文件

**4. 数据一致性与数据库设计**

- 设计 `user`、`resource` 两张表：合理设置唯一索引（账号、昵称、邮箱）、普通索引（用户 ID、资源类型、可见性）与外键级联删除；字符集统一 `utf8mb4` 支持 emoji
- **解决并发注册冲突**：业务层预查询提供友好提示的同时，捕获数据库 `UniqueConstraintError` 兜底，将两个请求同时通过预检查的场景正确转换为 409 冲突响应，而非 500 错误
- 资源删除采用**软删除**（`status` 置 0），保留数据可追溯，避免误删不可恢复

**5. 前端性能优化：自研虚拟滚动列表**

- 针对资源列表大数据量场景，手写 `VirtualList` 组件：占位容器撑起总高度 + `translateY` 偏移 + 可视区切片渲染，仅渲染可视区域约 15 个 DOM 节点
- 构建 1 万条确定性 mock 数据（生成函数 + 确定性伪随机，避免每次渲染数据漂移）进行对比压测，DOM 节点数与渲染耗时不再随总量线性增长
- 保留 `NormalList` 全量渲染组件作为对照组，可通过代码级开关切换，便于量化性能差异

**6. 前端工程化与组件复用**

- 封装 axios 实例：统一 baseURL 管理、10s 超时、请求拦截器自动注入 `Authorization` 头、响应拦截器拆包 `{ code, msg, data }` 并统一错误信息
- Pinia 状态管理：用户 store 统一管理 token 与用户资料，登录/登出自动同步 localStorage，解决「localStorage 已写入但页面登录态未更新」的状态不同步问题
- 路由体系：布局嵌套（主布局 + 独立登录注册页）、路由懒加载、全局守卫实现未登录拦截与登录后回跳原目标页
- 抽出 `ResourceRow`、`ResourceCard`、`UploadModal`、`EmptyState` 等公共组件，多页面复用，避免重复代码

**7. 工程规范**

- 编写完整 RESTful 接口文档（`docs/API.md`）：统一响应格式、状态码对照表、逐接口的参数表与失败场景清单
- 环境变量分层管理，敏感配置（数据库密码、JWT 密钥、云 AK/SK）全部收纳进 `.env` 并配置 `.gitignore`，同时提供 `.env.example` 协作模板

## 四、项目亮点（面试可展开）

| 亮点 | 说明 |
|---|---|
| **策略模式解耦存储** | 同一套业务代码通过环境变量切换本地 / 云端存储，符合开闭原则，新增阿里云 OSS 只需加一个 driver 文件 |
| **前端直传架构** | 大文件上传不经应用服务器，用「凭证签发 + 云端直传 + 结果登记」三段式解决服务器带宽瓶颈 |
| **前后端一致的校验规则** | 密码强度算法两端规则对齐，既保证体验（实时强度条）又保证安全（后端强制校验） |
| **1 万条数据虚拟滚动** | 自建方案不依赖第三方库，DOM 节点从 10000 降至 15，可量化对比 |
| **工程化完整性** | 三层架构 + 统一错误处理 + 接口文档 + 环境变量治理，具备团队协作与持续迭代基础 |
